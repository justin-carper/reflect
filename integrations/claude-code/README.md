# Claude Code integration

```sh
./install.sh --harness claude-code
```

Or by hand, which is all the installer does here:

```sh
mkdir -p ~/.claude/commands
cp integrations/claude-code/commands/reflect.md ~/.claude/commands/
```

Either way you get `/reflect`.

There is no nudge plugin here. Claude Code's hook system could support one, but the value is low enough that a periodic manual run is the honest recommendation — reflection yield is front-loaded, so running it more often does not find proportionally more.

## Where your transcripts live

`~/.claude/projects/<slugified-cwd>/<sessionId>.jsonl`, one JSON object per line. Override with `REFLECT_CLAUDE_PROJECTS` if yours are elsewhere.

## What gets filtered out

Most records under `type: "user"` were not typed by a person. The adapter excludes:

| Marker | Meaning |
|---|---|
| `isSidechain` | subagent session — the "user" text is a prompt the agent wrote |
| `isMeta` | harness-injected notice |
| `toolUseResult` | tool output delivered as a user record — 59% of user records in one real corpus |
| `sourceToolUseID` | message generated by a tool rather than a person |

It's a negative test rather than a positive one because there is no reliable positive marker: `promptSource: "typed"` appeared on only 2 of 315 user records in real data, so requiring it would throw away nearly everything.

## Note on repo grouping

Claude Code has no project-identity record, so the adapter uses `cwd` as the repo key. Git worktrees of the same repository therefore count as separate repos, which makes the concentration warning softer than it is for opencode. If you work in worktrees heavily, read that percentage as a floor.

## Auto memory is a different thing

Claude Code ships a native auto-memory feature that writes learnings to `~/.claude/projects/<project>/memory/MEMORY.md` and is viewable with `/memory`. It overlaps in spirit with this tool but differs in three ways: it is per-project, it is Claude-Code-only, and it writes continuously rather than on demand.

This tool is cross-harness, produces an auditable report you triage before anything changes, and is aimed specifically at finding rules you already wrote that are being ignored. Running both is reasonable. If you do, check whether auto memory has recorded anything that contradicts your written rules.
